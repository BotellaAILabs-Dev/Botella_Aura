## 1. The problem found in the codebase

A partial `BrandContext` already existed. It covered identity, audience, voice and knowledge, but only 2 of about 10 AI workflows used it. It had no memory, competitors, goals or channels, no definition of what counts as required, and no handling of conflicting values.

The same facts were stored in several places, and each workflow read its own subset:

- **Brand voice:** `brandVoiceNotes`, `brandVoiceProfile`, and each plan's `brandGuidelines`
- **Audience:** audience settings, `OutreachConfig`, `DiscoveryProfile`, and each plan's `audience`
- **Competitors:** `CompetitorProfile` and the trend watch list
- **Goals and channels:** audience settings and each plan's inputs

## 3. How conflicts are resolved

- Settings and onboarding answers take priority over plans, AI-seeded config, documents and learned patterns.
- Workspace settings take priority over a single month's plan. A plan value is used only when settings are empty, and it is marked as inferred.
- The generated voice profile takes priority over the notes it was written from. A difference between the two is expected, so it is not reported.
- Tracked competitors and the trend watch list are merged. Names that are only on the watch list are flagged.
- Tag lists are merged and de-duplicated regardless of case.
- Marketing Memory is advisory only. It never overrides the brand voice, the stated audience, or topics to avoid.
- Knowledge-base documents support what may be claimed. They never change a field.
- Nothing is dropped silently. Every overridden value is recorded with its source.

## 4. Existing behaviour that changed

- **`getBrandContext` now reads from the Business Context.** The campaign planner and the monthly planner use it, so they now follow the same sources and rules.
- **Lead scoring bug fixed.** Scoring described the company to the model using the brand voice notes, which describe tone rather than the business. It now receives the business description and a plain buyer profile, loaded once per discovery run instead of once per lead.
- **Duplicate audience tags fixed.** A new test showed that "Head of Ops" and "head of ops" both reached prompts, because tags were merged case-sensitively. The fix is in the shared merge, so the older code path benefits too.
